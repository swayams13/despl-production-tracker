**Known risk, not fixed today:** the dispatch "production complete" check (`assertUnitProductionComplete`, `src/lib/services/_shared.ts` ~983) passes when a unit has no schedule plans at all, so a unit on a job that never got a schedule could be packed and dispatched with nothing recorded. Reachable only for a job created without a delivery date; PR #128 stops the wizard doing that, and DESPL-320 and wizard-created jobs have plans. Recommended: one guard (zero plans on the current run → `UNIT_NOT_COMPLETE`, reason `NO_SCHEDULE`), on its own branch with `pnpm test:db`; several dispatch test fixtures need a plan added first. PR #132 closes the neighbouring hole (an empty batch could be released and dispatched).

**Not built, so nobody can decide it away today:** the Production Head's "Acknowledge" of out-of-sequence starts; the weld-map screen (J4b); drawing release and "release at risk" screens (H3 does nothing for new parts); adoption metrics; welding KPIs; a way to attach a QCP after job creation; a Production Head override on Excel switch-over; backup/on-prem decisions (D8, D27).
